# 第三章：Search-R1 项目架构详解

## 3.1 项目概述

Search-R1 是一个基于强化学习训练大型语言模型进行推理和搜索引擎调用交织能力的框架。它扩展了 DeepSeek-R1 的思想，允许模型在推理过程中调用外部搜索工具获取信息。

### 核心特性
- 支持多种 RL 算法：PPO、GRPO、REINFORCE
- 支持多种 LLMs：Llama3、Qwen2.5 等
- 支持多种搜索引擎：BM25、稠密检索、在线搜索
- 基于 veRL 框架构建

## 3.6 配置文件详解

### 训练配置结构 (train_ppo.sh)

```yaml
# 模型配置
actor_rollout_ref:
  model:
    path: "meta-llama/Llama-3.2-3B"  # 模型路径
    torch_dtype: "bfloat16"           # 精度类型
    use_flash_attention: true        # 启用 Flash Attention
  
  actor:
    optimizer:
      type: "adamw"
      lr: 1e-6                       # 学习率
  
  ref:
    max_batch_size: 16               # Reference 模型批次

# 数据配置  
data:
  train_files: ["data/nq_search/train.parquet"]
  val_files: ["data/nq_search/test.parquet"]
  max_prompt_length: 2048
  max_response_length: 2048

# 检索配置
retriever:
  url: "http://127.0.0.1:8000/retrieve"
  topk: 3                            # 返回 top-k 结果
  timeout: 30                        # 超时时间

# Agent 配置
agent:
  max_turns: 16                      # 最大推理轮次
  do_search: true                    # 是否启用搜索

# 训练配置
trainer:
  total_epochs: 1
  n_gpus_per_node: 8
  save_freq: 100                     # 保存频率

# 算法配置
algorithm:
  adv_estimator: "grpo"              # 或 "gae"
  gamma: 1.0
  lam: 0.95
  epsilon: 0.2                       # PPO clip 范围
```

## 3.7 关键类/函数一览

### search_r1/llm_agent/generation.py

| 类/函数 | 功能 |
|---------|------|
| `LLMGenerationManager` | Agent 生成管理器 |
| `run_llm_loop()` | 执行多轮推理循环 |
| `execute_predictions()` | 执行预测和处理搜索动作 |
| `batch_search()` | 批量调用检索服务 |
| `postprocess_predictions()` | 解析 action 标签 |

### verl/trainer/ppo/ray_trainer.py

| 类/函数 | 功能 |
|---------|------|
| `RayPPOTrainer` | Ray 分布式 PPO 训练器 |
| `fit()` | 主训练循环 |
| `_generate_samples()` | 生成训练样本 |
| `_update_actor()` | 更新 Actor |
| `_update_critic()` | 更新 Critic |
| `_validate()` | 验证和评估 |

### verl/trainer/ppo/core_algos.py

| 函数 | 功能 |
|------|------|
| `compute_gae_advantage()` | GAE 优势估计 |
| `compute_grpo_outcome_advantage()` | GRPO 优势计算 |
| `compute_policy_loss()` | PPO 策略损失 |
| `compute_value_loss()` | 价值函数损失 |
| `kl_penalty()` | KL 散度惩罚 |

## 3.8 架构设计亮点

### 1. 模块化设计
- 清晰的关注点分离
- 易于扩展新功能

### 2. 分布式训练
- 基于 Ray 的多 GPU/多节点支持
- 自动化资源管理

### 3. 灵活扩展
- 易于添加新的检索器
- 支持多种算法切换
