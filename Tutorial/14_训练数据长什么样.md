## 14.2 prompt 是怎么写出来的

先看 [`make_prefix()`](/Users/icarus/Documents/Search-R1-main/scripts/data_process/nq_search.py:19)：

```python
def make_prefix(dp, template_type):
    question = dp['question']

    if template_type == 'base':
        prefix = f"""Answer the given question. \
You must conduct reasoning inside <think> and </think> first every time you get new information. \
After reasoning, if you find you lack some knowledge, you can call a search engine by <search> query </search> and it will return the top searched results between <information> and </information>. \
You can search as many times as your want. \
If you find no further external knowledge needed, you can directly provide the answer inside <answer> and </answer>, without detailed illustrations. For example, <answer> Beijing </answer>. Question: {question}\n"""
```

这段话很关键，因为它等于在训练数据里提前规定了模型的交互协议：

- 推理写在 `<think>...</think>`
- 搜索动作写在 `<search>...</search>`
- 最终答案写在 `<answer>...</answer>`
- 检索返回内容会放在 `<information>...</information>`

也就是说，**模型不是天然知道怎么“调用搜索”**，而是数据里把这个格式教给了它。

## 14.3 一条训练样本是怎么构造的

再看 [`process_fn()`](/Users/icarus/Documents/Search-R1-main/scripts/data_process/nq_search.py:49)：

```python
def process_fn(example, idx):
    example['question'] = example['question'].strip()
    if example['question'][-1] != '?':
        example['question'] += '?'
    question = make_prefix(example, template_type=args.template_type)
    solution = {
        "target": example['golden_answers'],
    }

    data = {
        "data_source": data_source,
        "prompt": [{
            "role": "user",
            "content": question,
        }],
        "ability": "fact-reasoning",
        "reward_model": {
            "style": "rule",
            "ground_truth": solution
        },
        "extra_info": {
            'split': split,
            'index': idx,
        }
    }
    return data
```

这一段基本就是“训练样本定义”。

一条样本长这样：

```python
{
    "data_source": "nq",
    "prompt": [
        {
            "role": "user",
            "content": "带有 <think>/<search>/<answer> 说明的完整问题 prompt"
        }
    ],
    "ability": "fact-reasoning",
    "reward_model": {
        "style": "rule",
        "ground_truth": {
            "target": ["标准答案1", "标准答案2", ...]
        }
    },
    "extra_info": {
        "split": "train",
        "index": 123
    }
}
```

## 14.4 这几个字段分别有什么用

### `data_source`

这个字段后面会被 reward 逻辑拿来决定“用哪种打分函数”。

对应代码在：

- [`verl/trainer/main_ppo.py`](/Users/icarus/Documents/Search-R1-main/verl/trainer/main_ppo.py:25)

```python
def _select_rm_score_fn(data_source):
    if data_source in ['nq', 'triviaqa', 'popqa', 'hotpotqa', '2wikimultihopqa', 'musique', 'bamboogle']:
        return qa_em.compute_score_em
```

也就是说，如果 `data_source='nq'`，后面 reward 就会走 `qa_em.compute_score_em`。

### `prompt`

这就是模型最开始看到的输入。  
注意这里还只是“原始 QA 样本”，还没有 rollout 过程中的搜索结果。

### `reward_model.ground_truth`

这里存的是标准答案。  
后面 reward 计算时会从这里取出 `target`。

### `extra_info`

这是辅助信息，主要用于记录样本来自 train/test 的哪个位置，方便排查和分析。

## 14.6 训练脚本怎么接上这些数据

看训练脚本：

```bash

```

以及另一个脚本：

- [`train_ppo.sh`](/Users/icarus/Documents/Search-R1-main/train_ppo.sh:30)

```bash

```

所以数据流是：

```text
nq 原始数据
-> nq_search.py 转成统一样本格式
-> 保存成 parquet
-> train_grpo.sh / train_ppo.sh 指定 parquet 路径
-> trainer 读入 batch
```

## 14.7 这时候的“训练样本”和 rollout 样本不是一回事

这里很容易混。

### 数据集层面

这里的一条样本是：

```text
一个问题
+ 一个 prompt 模板
+ 一个标准答案
```

### RL 训练层面

当这条样本被送进模型生成后，它会变成一条 rollout 轨迹，里面还会多出：

- 模型生成的 `<think>`
- 模型发起的 `<search>`
- 检索返回的 `<information>`
- 最终 `<answer>`
- reward

所以可以这样理解：

```text
原始训练样本 = QA 数据
训练更新样本 = QA 数据跑出来的一条 rollout 轨迹
```
