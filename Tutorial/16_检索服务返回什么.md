# 16. 检索服务返回什么

这一章回答的问题是：

**当模型在 Search-R1 里发起一次搜索后，检索服务到底返回了什么？**

这是理解 `generation.py` 和 `retrieval_server.py` 接口约定的关键。

---

## 16.1 检索服务是一个独立的 HTTP 服务

启动入口通常是：

- [`retrieval_launch.sh`](/Users/icarus/Documents/Search-R1-main/retrieval_launch.sh:8)

```bash
python search_r1/search/retrieval_server.py --index_path $index_file \
                                            --corpus_path $corpus_file \
                                            --topk 3 \
                                            --retriever_name $retriever_name \
                                            --retriever_model $retriever_path \
                                            --faiss_gpu
```

也就是说，训练程序不会直接在内部 new 一个 retriever 来查，而是：

```text
单独启动一个检索服务
-> 暴露 HTTP 接口
-> generation.py 用 requests.post 去调
```

---

## 16.2 generation.py 发出去的请求长什么样

在 [`generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:450)：

```python
payload = {
    "queries": queries,
    "topk": self.config.topk,
    "return_scores": True
}

return requests.post(self.config.search_url, json=payload).json()
```

所以发给检索服务的请求大概长这样：

```json
{
  "queries": [
    "Who is Mike Barnett?"
  ],
  "topk": 3,
  "return_scores": true
}
```

这里的三个字段含义是：

- `queries`：一批待检索的问题
- `topk`：每个 query 返回几个文档
- `return_scores`：是否带回检索分数

---

## 16.3 服务端如何定义请求格式

看 [`retrieval_server.py`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:318)：

```python
class QueryRequest(BaseModel):
    queries: List[str]
    topk: Optional[int] = None
    return_scores: bool = False
```

这说明服务端明确要求请求体是：

```text
queries: 字符串列表
topk: 可选整数
return_scores: 布尔值
```

然后 API 入口在：

- [`retrieve_endpoint()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:326)

```python
@app.post("/retrieve")
def retrieve_endpoint(request: QueryRequest):
```

所以主程序访问的 URL 通常是：

```text
http://127.0.0.1:8000/retrieve
```

---

## 16.4 服务端拿到请求后做了什么

核心处理逻辑在：

- [`retrieve_endpoint()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:337)

```python
if not request.topk:
    request.topk = config.retrieval_topk

results, scores = retriever.batch_search(
    query_list=request.queries,
    num=request.topk,
    return_score=request.return_scores
)
```

也就是说：

1. 如果请求没传 `topk`，就用服务端默认值
2. 调用 `retriever.batch_search(...)`
3. 拿到 `results` 和 `scores`
4. 再整理成统一返回格式

---

## 16.5 返回值最外层长什么样

继续看 [`retrieve_endpoint()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:347)：

```python
resp = []
for i, single_result in enumerate(results):
    if request.return_scores:
        combined = []
        for doc, score in zip(single_result, scores[i]):
            combined.append({"document": doc, "score": score})
        resp.append(combined)
    else:
        resp.append(single_result)
return {"result": resp}
```

所以最终返回的最外层结构是：

```json
{
  "result": [
    [
      {
        "document": {...},
        "score": 12.34
      },
      {
        "document": {...},
        "score": 11.87
      }
    ]
  ]
}
```

这里为什么是两层列表？

- 第一层：对应 batch 里的多个 query
- 第二层：对应某个 query 的 topk 个文档

## 16.6 单个 document 长什么样

这取决于 retriever 类型。

### 情况 1：BM25

在 [`BM25Retriever._search()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:159) 里，如果索引里已经带原始文档，会组织成：

```python
results = [
    {
        'title': content.split("\n")[0].strip("\""),
        'text': "\n".join(content.split("\n")[1:]),
        'contents': content
    }
    for content in all_contents
]
```

也就是单篇文档大概长这样：

```json
{
  "title": "Evan Morris",
  "text": "Evan L. Morris ...",
  "contents": "Evan Morris\nEvan L. Morris ..."
}
```

### 情况 2：DenseRetriever

在 [`DenseRetriever._search()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:228) 里，返回的是：

```python
results = load_docs(self.corpus, idxs)
```

而 `load_docs()` 取的是 corpus 中的原始行：

- [`load_docs()`](/Users/icarus/Documents/Search-R1-main/search_r1/search/retrieval_server.py:34)

```python
results = [corpus[int(idx)] for idx in doc_idxs]
```

如果 corpus 按 README 推荐格式构造，一条记录大概是：

```json
{
  "id": "0",
  "contents": "Title\nPassage text..."
}
```

所以在 `generation.py` 里统一取：

```python
content = doc_item['document']['contents']
```

这也是为什么 `contents` 字段非常关键。

## 16.7 generation.py 实际依赖返回结构里的什么

看 [`_passages2string()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:460)：

```python
for idx, doc_item in enumerate(retrieval_result):
    content = doc_item['document']['contents']
    title = content.split("\n")[0]
    text = "\n".join(content.split("\n")[1:])
    format_reference += f"Doc {idx+1}(Title: {title}) {text}\n"
```

这说明 `generation.py` 实际依赖的是：

```text
response["result"][某个query][某个doc]["document"]["contents"]
```

然后把 `contents` 再拆成：

- 第一行作为标题
- 后面作为正文

最后拼成：

```text
Doc 1(Title: xxx) passage text...
Doc 2(Title: yyy) passage text...
```

---

## 16.8 这些结果最终怎么返回给模型

在 [`execute_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:390)：

```python
next_obs.append(f'\n\n<information>{search_results.pop(0).strip()}</information>\n\n')
```

所以检索服务返回的 JSON，不会原样喂给模型。  
而是会先经过：

```text
JSON
-> 取出 result
-> 取出每个 document.contents
-> 格式化成 Doc 1 / Doc 2 / Doc 3 文本
-> 包成 <information>...</information>
-> 再拼回模型上下文
```

---

## 16.9 一个完整例子

### 检索服务原始返回

```json
{
  "result": [
    [
      {
        "document": {
          "id": "123",
          "contents": "Mike Barnett\nMike Barnett is a sports agent..."
        },
        "score": 14.2
      },
      {
        "document": {
          "id": "456",
          "contents": "Sergei Fedorov\nSergei Fedorov later became..."
        },
        "score": 13.8
      }
    ]
  ]
}
```

### generation.py 格式化后

```text
<information>
Doc 1(Title: Mike Barnett) Mike Barnett is a sports agent...
Doc 2(Title: Sergei Fedorov) Sergei Fedorov later became...
</information>
```

### 模型下一轮看到的上下文

```text
原问题
本轮 <search>...</search>
<information>Doc 1... Doc 2...</information>
```

然后模型继续生成。

## 16.10 这一章最该记住什么

一句话总结：

**检索服务返回的是一个 JSON，其中最关键的是 `result -> document -> contents` 这条路径；`generation.py` 会把这些 `contents` 格式化成 `Doc 1 / Doc 2 / ...` 的文本，再包进 `<information>` 标签返回给模型。**
