# 18. 核心文件阅读路线

这一章回答一个实际问题：

**如果只想用有限时间读懂 Search-R1 的核心，应该按什么顺序看哪些文件，每个文件看什么。**

推荐顺序是：

```text
train_grpo.sh
-> search_r1/llm_agent/generation.py
-> verl/trainer/ppo/ray_trainer.py
-> verl/utils/reward_score/qa_em.py
```

这个顺序的目标不是读完所有细节，而是建立主线：

```text
训练怎么启动
-> rollout 怎么产生
-> trainer 什么时候调用 rollout 和 reward
-> reward 最后怎么计算
```

## 18.1 为什么先看 train_grpo.sh

文件：

- [`train_grpo.sh`](/Users/icarus/Documents/Search-R1-main/train_grpo.sh:1)

这个脚本是训练入口。它本身不实现算法，但它决定了训练程序的关键配置。

重点看这几类参数：

```bash
export BASE_MODEL='Qwen/Qwen2.5-3B'
export EXPERIMENT_NAME=nq-search-r1-grpo-qwen2.5-3b-em
```

这里决定使用哪个基座模型，以及实验名。

再看数据路径：

```bash
data.train_files=$TRAIN_DATA_DIR/train.parquet \
data.val_files=$TEST_DATA_DIR/test.parquet \
```

这里决定训练集和验证集从哪里读。

再看算法配置：

```bash
algorithm.adv_estimator=grpo \
```

这里说明当前训练使用的是 GRPO 相关的 advantage estimator。

再看检索配置：

```bash
max_turns=2 \
retriever.url="http://127.0.0.1:8000/retrieve" \
retriever.topk=3 \
```

这里决定：

- 最多几轮 search/answer
- 检索服务地址
- 每次检索返回几个文档

```python
@hydra.main(config_path='config', config_name='ppo_trainer', version_base=None)
```

所以这一步的调用关系是：

```text
train_grpo.sh
-> python3 -m verl.trainer.main_ppo
-> Hydra 合并配置
-> main(config)

```

读 `train_grpo.sh` 的目的不是看 shell 语法，而是搞清楚：

**训练开始前，哪些关键配置已经被定死。**

## 18.3 为什么第二个看 generation.py

文件：

- [`search_r1/llm_agent/generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:1)

这是 Search-R1 最核心的业务文件。它体现了这个项目最值钱的部分：

```text
多轮推理 + 工具调用 + RL rollout 管理
```

这个文件不负责更新模型参数。它负责的是：

```text
给定一批 prompt
-> 调模型生成
-> 解析 <search> 或 <answer>
-> 如果 search，调用检索服务
-> 把结果包装成 <information>
-> 拼回上下文继续生成
-> 最终输出一条 rollout 轨迹
```

## 18.4 generation.py 先看哪些函数

先看配置类：

- [`GenerationConfig`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:13)

```python
@dataclass
class GenerationConfig:
    max_turns: int
    max_start_length: int
    max_prompt_length: int 
    max_response_length: int
    max_obs_length: int
    num_gpus: int
    no_think_rl: bool=False
    search_url: str = None
    topk: int = 3
```

这里定义的是 rollout 阶段需要的参数。

然后看主循环：

- [`run_llm_loop()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:220)

这是整个文件最重要的函数。

你只需要先抓住这几步：

```text
1. 初始化 active_mask，记录哪些样本还没结束
2. 调 actor_rollout_wg.generate_sequences 生成文本
3. 用 _postprocess_responses 截断到 </search> 或 </answer>
4. 用 execute_predictions 执行动作
5. 如果 search，把 information 拼回上下文
6. 如果 answer，该样本结束
7. 最后 _compose_final_output 返回完整 rollout
```

然后看动作解析：

- [`postprocess_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:407)

```python
pattern = r'<(search|answer)>(.*?)</\1>'
```

这句说明模型发起搜索的方式不是函数调用，而是输出文本标签。

最后看搜索请求：

- [`_batch_search()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:450)

```python
payload = {
    "queries": queries,
    "topk": self.config.topk,
    "return_scores": True
}
return requests.post(self.config.search_url, json=payload).json()
```

这里完成真实 HTTP 搜索请求。

## 18.5 为什么 generation.py 对简历最有价值

因为它可以被清楚地描述成一个工程能力点：

```text
理解并梳理 Search-R1 中多轮 LLM Agent rollout 流程，包括 search/answer 动作解析、检索服务调用、observation 拼接和轨迹输出。
```

这比只说“看过 PPO/GRPO”更具体。

如果后面做改进，优先也可以围绕这个文件：

- 搜索请求加 timeout
- 检索失败时加 fallback
- 记录每轮 search query 和返回文档数
- 对非法 action 做更明确的统计
- 给 `_passages2string()` 增加返回结构校验

这些改进都能直接服务于“可运行、可排错、可解释”。

## 18.8 第四个看 qa_em.py

文件：

- [`verl/utils/reward_score/qa_em.py`](/Users/icarus/Documents/Search-R1-main/verl/utils/reward_score/qa_em.py:1)

这个文件负责规则奖励。

最核心的是：

- [`extract_solution()`](/Users/icarus/Documents/Search-R1-main/verl/utils/reward_score/qa_em.py:54)
- [`compute_score_em()`](/Users/icarus/Documents/Search-R1-main/verl/utils/reward_score/qa_em.py:85)

`extract_solution()` 会从完整输出里找：

```python
answer_pattern = r'<answer>(.*?)</answer>'
```

`compute_score_em()` 会做：

```python
if answer is None:
    return 0
else:
    if em_check(answer, ground_truth['target']):
        return score
    else:
        return format_score
```

所以 reward 规则可以简化成：

```text
没有合法 answer -> 0
有合法 answer 但答案错 -> format_score，默认通常也是 0
有合法 answer 且答案对 -> 1
```

## 18.9 qa_em.py 和 main_ppo.py 的关系

`qa_em.py` 不是自己被 trainer 调用的。

它是通过 `main_ppo.py` 的 `RewardManager` 被接入训练流程：

- [`main_ppo.py`](/Users/icarus/Documents/Search-R1-main/verl/trainer/main_ppo.py:25)

```python
def _select_rm_score_fn(data_source):
    if data_source in ['nq', 'triviaqa', 'popqa', 'hotpotqa', '2wikimultihopqa', 'musique', 'bamboogle']:
        return qa_em.compute_score_em
```

然后：

- [`main_ppo.py`](/Users/icarus/Documents/Search-R1-main/verl/trainer/main_ppo.py:78)

```python
score = compute_score_fn(
    solution_str=sequences_str,
    ground_truth=ground_truth,
    format_score=self.format_score
)
```

所以 reward 链路是：

```text
RewardManager
-> 根据 data_source 选择 qa_em.compute_score_em
-> qa_em 提取 <answer>
-> 和 ground_truth['target'] 做 EM 匹配
```

## 18.10 四个文件合起来的主链路

把这四个文件串起来：

```text
train_grpo.sh
    |
    | 传入 data / model / algorithm / retriever 配置
    v
main_ppo.py
    |
    | 创建 RayPPOTrainer，挂上 RewardManager
    v
ray_trainer.py
    |
    | 创建 GenerationConfig 和 LLMGenerationManager
    v
generation.py
    |
    | 跑多轮 search/answer rollout
    v
ray_trainer.py
    |
    | 拿 rollout 调 reward_fn
    v
main_ppo.py / RewardManager
    |
    | 调 qa_em.compute_score_em
    v
qa_em.py
    |
    | 返回 reward
    v
ray_trainer.py
    |
    | 后续计算 advantage 并更新 actor
```

注意：虽然 `main_ppo.py` 不在本章标题的重点里，但它是 `RewardManager` 和 `RayPPOTrainer` 的装配入口，理解链路时不能完全跳过。

## 18.11 推荐的实际阅读节奏

第一轮只读主干：

```text
train_grpo.sh：20 分钟
generation.py：90 分钟
ray_trainer.py：60 分钟
qa_em.py：30 分钟
```

第二轮带问题读：

```text
问题 1：max_turns/topk/search_url 从哪里来？
问题 2：模型输出 search 后，谁去调检索服务？
问题 3：检索结果怎么进入下一轮 prompt？
问题 4：最终 reward 为什么能找到 ground_truth？
问题 5：GRPO 是在哪里通过 config 生效的？
```

第三轮开始找可改进点：

```text
脚本变量是否一致
检索请求是否有 timeout
检索返回结构是否做校验
非法 action 是否有统计
reward 解析是否有测试
```

## 18.12 这一章最该记住什么

一句话总结：

**`train_grpo.sh` 决定配置，`generation.py` 产生 search-enhanced rollout，`ray_trainer.py` 把 rollout 接入训练循环，`qa_em.py` 给最终答案打规则奖励。**

这个主线就是后续写简历和排 bug 的基础。
