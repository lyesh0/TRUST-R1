## 19.7 generation.py：多轮 search rollout 执行器

文件：

- [`search_r1/llm_agent/generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:1)

这个文件的作用是：

```text
把一批 prompt 跑成带 search/information/answer 的 rollout 轨迹。
```

它不是训练更新逻辑，也不是 reward 逻辑。

它负责：

```text
模型生成
-> 动作解析
-> 检索调用
-> observation 拼接
-> 下一轮生成
-> 输出完整轨迹
```

## 19.8 generation.py 的配置对象

配置类：

- [`GenerationConfig`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:13)

```python
@dataclass
class GenerationConfig:
    max_turns: int
    max_start_length: int
    max_prompt_length: int 
    max_response_length: int
    max_obs_length: int
    num_gpus: int
    no_think_rl: bool=False
```

这里不是最终配置来源。最终数值来自 `ray_trainer.py` 创建它时传入的 `self.config`。

例如：

```text

-> Hydra config
-> ray_trainer.py 的 self.config.retriever.topk
-> GenerationConfig.topk
-> generation.py 的 self.config.topk
```

## 19.10 generation.py 的主循环

主函数：

- [`run_llm_loop()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:220)

初始化状态：

```python
original_left_side = {'input_ids': initial_input_ids[:, -self.config.max_start_length:]}
original_right_side = {'responses': initial_input_ids[:, []], 'responses_with_info_mask': initial_input_ids[:, []]}
active_mask = torch.ones(gen_batch.batch['input_ids'].shape[0], dtype=torch.bool)
rollings = gen_batch
```

含义：

- `original_left_side`：原始 prompt
- `original_right_side`：后续生成内容
- `active_mask`：哪些样本还没结束
- `rollings`：当前轮输入给模型的上下文

主循环：

```python
for step in range(self.config.max_turns):
```

这表示最多跑 `max_turns` 轮 search/answer 交互。

## 19.11 generation.py 如何调用模型生成

在主循环里：

```python
rollings_active = DataProto.from_dict({
    k: v[active_mask] for k, v in rollings.batch.items()
})
gen_output = self._generate_with_gpu_padding(rollings_active)
```

`active_mask` 用来筛掉已经结束的样本，只让未完成样本继续生成。

`_generate_with_gpu_padding()` 最终会调用：

```python
self.actor_rollout_wg.generate_sequences(...)
```

也就是说，`generation.py` 本身不实现大模型推理，它只是管理调用流程。

## 19.12 generation.py 如何截断模型输出

生成后进入：

- [`_postprocess_responses()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:54)

```python
responses_str = [resp.split('</search>')[0] + '</search>'
         if '</search>' in resp 
         else resp.split('</answer>')[0] + '</answer>'
         if '</answer>' in resp 
         else resp
         for resp in responses_str]
```

作用：

```text
如果生成里出现 </search>，截断到 </search>
如果生成里出现 </answer>，截断到 </answer>
否则保留原样
```

这一步的目的，是把模型当前轮输出整理成一个动作。

## 19.13 generation.py 如何解析 search/answer

动作解析在：

- [`postprocess_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:407)

```python
pattern = r'<(search|answer)>(.*?)</\1>'
match = re.search(pattern, prediction, re.DOTALL)
```

能识别两种动作：

```text
<search>query</search>
<answer>final answer</answer>
```

匹配成功后：

```python
action = match.group(1)
content = match.group(2).strip()
```

如果模型输出不符合格式：

```python
action = None
content = ''
```

后面会进入非法动作分支。

## 19.14 generation.py 如何执行动作

动作执行在：

- [`execute_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:353)

先解析：

```python
cur_actions, contents = self.postprocess_predictions(predictions)
```

再收集 search query：

```python
search_queries = [content for action, content in zip(cur_actions, contents) if action == 'search']
```

如果允许搜索：

```python
search_results = self.batch_search(search_queries)
```

然后分三种情况：

```python
if action == 'answer':
    dones.append(1)
elif action == 'search':
    next_obs.append(f'\n\n<information>{search_results.pop(0).strip()}</information>\n\n')
    dones.append(0)
else:
    next_obs.append('My previous action is invalid...')
    dones.append(0)
```

含义：

- `answer`：样本结束
- `search`：返回 observation，继续下一轮
- 非法格式：给模型格式提示，继续下一轮

## 19.16 generation.py 如何更新下一轮上下文

搜索结果变成 `next_obs` 后，会进入：

- [`_process_next_obs()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:77)
- [`_update_rolling_state()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:93)

核心拼接逻辑：

```python
new_input_ids = self.tensor_fn.concatenate_with_padding([
    rollings.batch['input_ids'],
    cur_responses,
    next_obs_ids
])
```

含义：

```text
旧上下文
+ 当前轮模型输出
+ 当前轮检索 observation
= 下一轮模型输入
```

这就是多轮 search rollout 能持续进行的原因。

## 19.20 ray_trainer.py 中 batch 如何进入 rollout

训练循环里：

## 19.23 ray_trainer.py 什么时候调用 reward

在 advantage 计算阶段：

- [`ray_trainer.py`](/Users/icarus/Documents/Search-R1-main/verl/trainer/ppo/ray_trainer.py:778)

## 19.28 qa_em.py 如何提取 <answer>

函数：

- [`extract_solution()`](/Users/icarus/Documents/Search-R1-main/verl/utils/reward_score/qa_em.py:62)

```python
answer_pattern = r'<answer>(.*?)</answer>'
match = re.finditer(answer_pattern, solution_str, re.DOTALL)
matches = list(match)
```

然后：

```python
if len(matches) <= 1:
    return None

return matches[-1].group(1).strip()
```

这里有一个很重要的实现细节：

```text
如果 <answer> 匹配数量小于等于 1，直接返回 None。
只有出现 2 个或更多 <answer> 时，才取最后一个。
```

这和很多人直觉不同。原因可能和 chat template 或训练输出中 prompt 示例也包含 `<answer>` 有关：prompt 示例里可能已经有一个 `<answer> Beijing </answer>`，模型真正答案是第二个。

排查 reward 异常时，这个点必须重点看。

## 19.29 qa_em.py 如何返回最终分数

函数：

- [`compute_score_em()`](/Users/icarus/Documents/Search-R1-main/verl/utils/reward_score/qa_em.py:85)

```python
answer = extract_solution(solution_str=solution_str)
```

然后：

```python
if answer is None:
    return 0
else:
    if em_check(answer, ground_truth['target']):
        return score
    else:
        return format_score
```

默认情况下：

- `score=1.`
- `format_score=0.`

所以通常是：

```text
没有合法答案 -> 0
有合法答案但答错 -> 0
有合法答案且答对 -> 1
```

注意：

```text
当前默认配置下，“格式错”和“格式对但答案错”都是 0。
```

如果你想让模型先学会格式，可以把 `format_score` 设成大于 0，但当前 `RewardManager` 默认是 0。

```python
compute_score_fn = _select_rm_score_fn(data_source)
score = compute_score_fn(solution_str=sequences_str, ground_truth=ground_truth, format_score=self.format_score)
```

最后 reward 写到 response 最后一个 token：

```python
reward_tensor[i, valid_response_length - 1] = score
```

所以完整 reward 调用链是：

```text
ray_trainer.py
-> self.reward_fn(batch)
-> main_ppo.py / RewardManager.__call__
-> qa_em.compute_score_em
-> reward_tensor
```

## 19.31 四个文件合起来怎么讲

你可以这样概括：

```text
train_grpo.sh
负责启动训练并传入关键配置。

generation.py
负责把 prompt 跑成带 search/information/answer 的 rollout。

ray_trainer.py
负责把 rollout、logprob、reward、advantage、actor update 串成训练循环。

qa_em.py
负责从最终输出里提取答案，并和 ground_truth 做 EM 打分。
```

如果写进简历，可以压缩成：

```text
梳理 Search-R1 中从 GRPO 训练配置、LLM Agent 多轮检索 rollout、规则奖励计算到 actor 更新的主链路，定位关键模块间的数据流和控制流。
```

- `generation.py / _batch_search`

- `qa_em.py / extract_solution`
- 输出里 `<answer>` 的数量
- `ground_truth['target']`
- `format_score`

先看：

- `train_grpo.sh / algorithm.adv_estimator=grpo`
- `ray_trainer.py / compute_advantage`
- `ray_trainer.py / use_critic=False`

## 19.33 本章结论

这四个文件分别对应训练系统的四个关键阶段：

```text
配置入口：train_grpo.sh
轨迹生成：generation.py
训练调度：ray_trainer.py
奖励计算：qa_em.py
```

读代码时不要把所有文件混在一起。先判断当前问题属于哪个阶段，再进入对应文件定位。
