# 21. 项目主流程代码串讲

这一章只做一件事：

**把 Search-R1 的主流程按代码顺序串起来。**

目标不是把所有 `verl` 细节吃透，而是能把下面这条主线讲清楚：

```text
数据处理
-> prompt 组织
-> 模型生成 search/answer
-> 检索服务返回结果
-> 结果拼回上下文
-> reward 计算
-> PPO/GRPO 更新
```

如果你能把这一条链讲清楚，说明你已经具备：

- 看懂项目主流程的能力
- 运行和排错的基础
- 写简历项目描述的基本素材

def process_fn(example, idx):

## 21.2 第二步：prompt 组织

prompt 模板在：

- [`make_prefix()`](/Users/icarus/Documents/Search-R1-main/scripts/data_process/nq_search.py:19)

```python
prefix = f"""Answer the given question. \
You must conduct reasoning inside <think> and </think> first every time you get new information. \
After reasoning, if you find you lack some knowledge, you can call a search engine by <search> query </search> and it will return the top searched results between <information> and </information>. \
You can search as many times as your want. \
If you find no further external knowledge needed, you can directly provide the answer inside <answer> and </answer>, without detailed illustrations. For example, <answer> Beijing </answer>. Question: {question}\n"""
```

这里做的不是“普通提示词工程”，而是规定一套交互协议：

- 推理用 `<think>...</think>`
- 搜索用 `<search>...</search>`
- 检索结果会放在 `<information>...</information>`
- 最终答案用 `<answer>...</answer>`

这一步很重要，因为后面的 `generation.py` 完全依赖这个协议。

换句话说：

```text
prompt 不只是给模型提问
prompt 还告诉模型“你应该怎样调用工具”
```

## 21.6 第六步：系统解析模型动作

动作解析在：

- [`generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:420)

```python
pattern = r'<(search|answer)>(.*?)</\1>'
match = re.search(pattern, prediction, re.DOTALL)
```

如果匹配成功：

```python
action = match.group(1)
content = match.group(2).strip()
```

所以这一步的语义是：

```text
模型不是直接调用 Python 函数
而是输出一段符合协议的文本
系统再把它解释成 action + content
```

例如：

```text
<search>Mike Barnett CSKA Moscow general manager</search>
```

会被解析成：

- `action = "search"`
- `content = "Mike Barnett CSKA Moscow general manager"`

## 21.11 你现在应该怎么记这条主线

压缩成最短版本：

```text
1. nq_search.py 把 QA 数据转成 parquet 样本
2. prompt 里规定了 <search>/<information>/<answer> 协议
3. train_grpo.sh 把数据路径、GRPO、检索配置传给 trainer
4. ray_trainer.py 取 batch，调用 generation.py 跑多轮 rollout
5. generation.py 解析 search/answer，调用 retrieval_server.py
6. 检索结果被格式化成 <information> 拼回上下文
7. rollout 完成后，RewardManager + qa_em.py 根据最终 answer 算 reward
8. ray_trainer.py 用 reward 计算 advantage，并更新 actor
```

## 21.12 学完这条主流程后，排错应该怎么看

### 数据不对

先看：

- `nq_search.py`
- parquet 路径
- `RLHFDataset`

### 模型不会 search

先看：

- prompt 模板
- `generation.py / postprocess_predictions`

### 搜索报错

先看：

- `generation.py / _batch_search`
- `retrieval_server.py / /retrieve`

### reward 一直是 0

先看：

- `RewardManager`
- `qa_em.py / extract_solution`

### GRPO / PPO 行为不符合预期

先看：

- `train_grpo.sh / algorithm.adv_estimator`
- `ray_trainer.py / compute_advantage`
- `ray_trainer.py / use_critic`

## 21.13 本章结论

Search-R1 的主流程不是分散的，而是很清楚地分布在几段代码里：

```text
数据和 prompt：nq_search.py
训练配置：train_grpo.sh
rollout：generation.py
检索服务：retrieval_server.py
reward：main_ppo.py + qa_em.py
更新：ray_trainer.py
```

把这几个文件串起来看，比单独啃 `verl/` 目录有效得多。
