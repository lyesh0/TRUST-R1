# 第一章：强化学习基础

## 1.1 什么是强化学习？

强化学习（Reinforcement Learning，RL）是一种机器学习范式，智能体（Agent）通过与环境（Environment）交互，学习最优策略（Policy）以最大化累计奖励（Reward）。

### 核心要素
| 要素 | 符号 | 说明 |
|------|------|------|
| 智能体 | Agent | 学习者和决策者 |
| 环境 | Environment | Agent 交互的外部世界 |
| 状态 | State (s) | 环境的当前描述 |
| 动作 | Action (a) | Agent 可采取的行为 |
| 奖励 | Reward (r) | 对动作的反馈信号 |
| 策略 | Policy (π) | 状态到动作的映射 |

### 学习过程
```
┌─────────────────────────────────────────────────────┐
│                    强化学习循环                      │
│                                                     │
│    ┌────────┐    状态 s     ┌────────┐              │
│    │  Agent │◄────────────►│ 环境   │              │
│    └────┬───┘              └───┬────┘              │
│         │                      │                   │
│         │ 动作 a               │                   │
│         │ 奖励 r               │                   │
│         │ 下一状态 s'          │                   │
│         │                      │                   │
│         └──────────────────────┘                   │
└─────────────────────────────────────────────────────┘
```

## 1.2 马尔可夫决策过程 (MDP)

MDP 是强化学习的数学框架，定义为一个五元组 (S, A, P, R, γ)：

- **S**: 状态空间
- **A**: 动作空间
- **P**: 状态转移概率 P(s'|s,a)
- **R**: 奖励函数 R(s,a)
- **γ**: 折扣因子 (0-1)

### 马尔可夫性质
> 未来只依赖于当前状态，不依赖于过去的历史状态。

### 示例：Search-R1 中的 MDP

在 Search-R1 项目中，MDP 可以定义为：
- **状态 s**: 当前对话上下文（包括用户问题、历史搜索结果）
- **动作 a**: 生成下一个 token，或者触发搜索动作
- **奖励 r**: 基于最终答案正确性的延迟奖励
- **折扣 γ**: 通常设为 1.0（无折扣）

## 1.3 价值函数

### 状态价值函数 V(s)

从状态 s 开始，按照策略 π 行动的预期累计奖励：

$$V^\pi(s) = \mathbb{E}_\pi \left[ \sum_{t=0}^{\infty} \gamma^t R(s_t, a_t) \mid s_0 = s \right]$$

### 动作价值函数 Q(s,a)

从状态 s 执行动作 a 后的预期累计奖励：

$$Q^\pi(s,a) = \mathbb{E}_\pi \left[ \sum_{t=0}^{\infty} \gamma^t R(s_t, a_t) \mid s_0 = s, a_0 = a \right]$$

### 贝尔曼方程

价值函数的递归定义：

$$V^\pi(s) = \sum_a \pi(a|s) \sum_{s'} P(s'|s,a)[R(s,a,s') + \gamma V^\pi(s')]$$

## 1.4 策略梯度方法

### 策略梯度定理

$$\nabla_\theta J(\theta) = \mathbb{E}_{s \sim d^\pi, a \sim \pi_\theta} \left[ \nabla_\theta \log \pi_\theta(a|s) \cdot Q^{\pi_\theta}(s,a) \right]$$

### REINFORCE 算法

1. 使用当前策略 π_θ 生成轨迹 τ
2. 计算每一步的回报 G_t
3. 更新策略：θ ← θ + α ∇_θ log π_θ(a_t|s_t) G_t

## 1.5 PPO 算法详解

### PPO 的核心思想

PPO（Proximal Policy Optimization）通过限制策略更新的幅度，避免策略变化过大导致的性能崩溃。

### 重要性采样

使用旧策略 π_old 生成样本，用新策略 π_θ 进行更新的技术：

$$L = \mathbb{E}_{a \sim \pi_{old}} \left[ \frac{\pi_\theta(a|s)}{\pi_{old}(a|s)} Q(s,a) \right]$$

### PPO 目标函数

$$L^{CLIP}(\theta) = \mathbb{E}_{s,a \sim \pi_{old}} \left[ \min \left( \frac{\pi_\theta(a|s)}{\pi_{old}(a|s)} A(s,a), \text{clip} \left( \frac{\pi_\theta(a|s)}{\pi_{old}(a|s)}, 1-\epsilon, 1+\epsilon \right) A(s,a) \right) \right]$$

其中：
- **A(s,a)**: 优势函数（Advantage）
- **ε**: 超参数，通常为 0.2
- **clip()**: 将比率限制在 [1-ε, 1+ε] 范围内

### PPO 算法流程

```
┌─────────────────────────────────────────────────────────┐
│                      PPO 算法流程                        │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  for iteration = 1, 2, ... do                          │
│      for actor = 1, 2, ..., N do                        │
│          使用 π_θ_old 收集轨迹                           │
│      end for                                            │
│                                                         │
│      计算优势估计 Â(s_t, a_t)                           │
│                                                         │
│      for epoch = 1, 2, ..., K do                        │
│          使用随机梯度上升优化 L^{CLIP+VF+S}(θ)          │
│      end for                                            │
│                                                         │
│      θ_old ← θ                                         │
│  end for                                                │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 1.6 GRPO 算法

GRPO（Group Relative Policy Optimization）是 DeepSeek-R1 使用的变体。

### 与 PPO 的区别
1. **不需要 Critic 模型**：使用组内相对基准
2. **更简单的优势估计**：直接用奖励比较

### GRPO 优势计算

$$A_i = \frac{r_i - \mu_G}{\sigma_G}$$

其中 G 是同一 prompt 生成的多个样本组，μ_G 和 σ_G 是组内均值和标准差。

### GRPO 伪代码

```python
def grpo_update(rewards, logprobs_old, logprobs_new):
    """
    GRPO 优势计算和策略更新
    """
    # 重组为 (num_prompts, group_size) 形状
    # 每个 prompt 生成 group_size 个样本
    
    group_mean = rewards.mean(dim=-1, keepdim=True)
    group_std = rewards.std(dim=-1, keepdim=True) + 1e-8
    
    # 计算优势（组内相对）
    advantages = (rewards - group_mean) / group_std
    
    # 计算策略损失（与 PPO 相同）
    ratio = torch.exp(logprobs_new - logprobs_old)
    
    # Clip
    clipped_ratio = torch.clamp(ratio, 1-0.2, 1+0.2)
    
    # 取较小值
    loss = -torch.min(ratio * advantages, clipped_ratio * advantages).mean()
    
    return loss
```

## 1.7 优势函数估计 (GAE)

GAE（Generalized Advantage Estimation）平衡偏差和方差：

$$A_{GAE}(s_t, a_t) = \sum_{l=0}^{\infty} (\gamma\lambda)^l \delta_{t+l}$$

其中 δ_t = r_t + γV(s_{t+1}) - V(s_t)

### 超参数 λ
- λ = 0：等同于单步 TD 误差（高偏差，低方差）
- λ = 1：等同于蒙特卡洛（低偏差，高方差）
- 常用 λ = 0.95

### GAE 实现

```python
def compute_gae_advantage(
    values: torch.Tensor,      # V(s_t)
    rewards: torch.Tensor,    # r_t
    gamma: float = 0.99,
    lam: float = 0.95
) -> torch.Tensor:
    """
    计算 GAE 优势估计
    """
    advantages = torch.zeros_like(values)
    gae = 0
    
    # 反向计算
    for t in reversed(range(len(rewards))):
        if t == len(rewards) - 1:
            next_value = 0  # 终止状态
        else:
            next_value = values[:, t + 1]
        
        delta = rewards[:, t] + gamma * next_value - values[:, t]
        gae = delta + gamma * lam * gae
        advantages[:, t] = gae
    
    return advantages
```

## 1.8 强化学习在 LLM 中的应用

### 为什么 LLM 需要强化学习？

1. **对齐训练**：让模型输出符合人类偏好（如 RLHF）
2. **推理增强**：提升复杂任务的推理能力（如 DeepSeek-R1）
3. **工具使用**：学习调用外部工具（搜索、代码执行）

### LLM 强化学习的挑战

| 挑战 | 说明 |
|------|------|
| 动作空间巨大 | 词表大小的离散空间（~100k tokens） |
| 奖励稀疏 | 很多中间步骤没有明确奖励 |
| 长序列 | 信用分配问题严重 |
| 连续动作 | 输出是连续 token 序列 |

### Search-R1 的创新

1. **多轮搜索交互**：LLM 可以多次调用搜索 API 直到获得满意答案
2. **基于规则的奖励**：使用精确匹配（EM）作为奖励信号
3. **端到端训练**：从零训练 LLM 的搜索推理能力

## 1.9 KL 散度约束

### 为什么需要 KL 约束？

防止策略更新幅度过大，导致性能崩溃。

### KL 惩罚项

$$L_{KL} = \beta \cdot KL(\pi_{old} || \pi_{new})$$

其中 β 是 KL 系数，控制约束强度。

### 自适应 KL 控制器

```python
class AdaptiveKLController:
    def __init__(self, kl_coef_init=0.1, target_kl=0.02):
        self.kl_coef = kl_coef_init
        self.target_kl = target_kl
    
    def update(self, kl_value):
        # 根据实际 KL 值调整系数
        if kl_value < self.target_kl / 1.5:
            self.kl_coef *= 0.8  # 减小约束
        elif kl_value > self.target_kl * 1.5:
            self.kl_coef *= 1.2  # 增加约束
        return self.kl_coef
```
