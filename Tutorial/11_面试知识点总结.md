# 第十一章：面试知识点总结

## 11.1 强化学习面试题

### 11.1.1 基础概念

**Q1: 什么是马尔可夫决策过程（MDP）？**

MDP 是强化学习的数学框架，定义为一个五元组 (S, A, P, R, γ)：
- S: 状态空间
- A: 动作空间
- P: 状态转移概率 P(s'|s,a)
- R: 奖励函数 R(s,a)
- γ: 折扣因子

MDP 满足马尔可夫性质：未来只依赖于当前状态，不依赖历史。

**Q2: 什么是价值函数？V(s) 和 Q(s,a) 的区别？**

V(s) 是状态价值函数，表示从状态 s 开始按照策略 π 行动的预期累计奖励。

Q(s,a) 是动作价值函数，表示从状态 s 执行动作 a 后的预期累计奖励。

关系：V(s) = E[Q(s,a)]，即 Q 对动作的期望。

**Q3: 贝尔曼方程的含义？**

价值函数的递归定义：

V(s) = Σ_a π(a|s) Σ_{s'} P(s'|s,a)[R(s,a,s') + γV(s')]

核心思想：当前价值 = 即时奖励 + 折扣后的未来价值

### 11.1.2 PPO 算法

**Q4: PPO 的核心思想是什么？**

PPO（Proximal Policy Optimization）通过限制策略更新的幅度，避免策略变化过大导致的性能崩溃。

关键点：
1. 使用重要性采样
2. Clip 策略比率
3. 悲观估计（取较小值）

**Q5: 为什么 PPO 需要 clip？**

如果策略更新幅度过大，可能导致：
1. 性能崩溃
2. 训练不稳定
3. 偏离最优策略

Clip 将策略比率限制在 [1-ε, 1+ε] 范围内，确保更新不会太激进。

**Q6: PPO 和 TRPO 的区别？**

| 方面 | PPO | TRPO |
|------|-----|------|
| 约束方式 | 软约束（clip） | 硬约束（KL） |
| 实现复杂度 | 简单（一阶优化） | 复杂（需要共轭梯度） |
| 采样效率 | 高 | 中 |
| 稳定性 | 好 | 好 |

### 11.1.3 GRPO 算法

**Q7: GRPO 和 PPO 的区别？**

GRPO（Group Relative Policy Optimization）：
1. 不需要 Critic 模型
2. 使用组内相对基准计算优势
3. 更简单，内存效率高

公式：A_i = (r_i - μ_G) / σ_G

其中 G 是同一 prompt 生成的多个样本组。

**Q8: GRPO 的优缺点？**

优点：
- 无需训练 Critic，节省内存
- 实现简单
- 在推理任务上效果好

缺点：
- 优势估计可能不稳定
- 不适合需要精确价值估计的任务

### 11.1.4 优势估计

**Q9: 什么是 GAE？有什么作用？**

GAE（Generalized Advantage Estimation）平衡偏差和方差：

A_GAE(t) = Σ_l (γλ)^l δ_{t+l}

其中 δ_t = r_t + γV(s_{t+1}) - V(s_t)

λ=0：单步 TD（高偏差，低方差）
λ=1：蒙特卡洛（低偏差，高方差）
常用 λ=0.95

**Q10: 什么是信用分配问题？**

在长序列任务中，很难判断哪一步对最终结果贡献最大。

例如：推理任务中，模型生成 1000 token 后才得到答案，很难知道之前每步的好坏。

解决方案：GAE、蒙特卡洛、时序差分等。

## 11.2 LLM Agent 面试题

### 11.2.1 Agent 基础

**Q11: 什么是 LLM Agent？**

基于大型语言模型的智能系统，能够：
- 理解自然语言指令
- 进行多步推理
- 调用外部工具
- 与环境交互

核心能力：规划、记忆、工具使用、自我反思。

**Q12: ReAct 范式的核心思想？**

"Thought → Action → Observation" 循环：
1. Thought：模型思考下一步该做什么
2. Action：执行动作（如搜索）
3. Observation：获取结果并反馈

**Q13: Agent 和普通 LLM 的区别？**

| 方面 | 普通 LLM | LLM Agent |
|------|---------|-----------|
| 交互方式 | 单次问答 | 多轮交互 |
| 工具使用 | 无 | 有 |
| 规划能力 | 弱 | 强 |
| 环境交互 | 无 | 有 |

## 11.3 系统设计面试题

### 11.3.1 分布式训练

**Q18: 如何设计一个 RL 训练系统？**

核心组件：
1. 数据加载器：高效加载训练数据
2. Rollout Worker：生成样本
3. Reward Calculator：计算奖励
4. Trainer：更新模型

关键考虑：
- 多 GPU/多节点扩展
- 通信效率
- 容错处理

**Q19: FSDP vs DDP 的区别？**

DDP（Distributed Data Parallel）：
- 复制所有模型到每个 GPU
- 梯度 all-reduce

FSDP（Fully Sharded Data Parallel）：
- 模型分片到不同 GPU
- 减少内存占用
- 通信更复杂

### 11.3.2 检索系统

**Q20: 如何设计一个高效的检索系统？**

组件：
1. 索引构建：BM25、FAISS、HNSW
2. 查询处理：编码、重排序
3. 服务部署：FastAPI、gRPC

优化：
- 缓存热点查询
- 批量处理
- 异步 IO

## 11.4 项目亮点总结

### 11.4.1 如何描述 Search-R1 项目？

**项目简介**
Search-R1 是一个基于强化学习训练 LLM 进行搜索增强推理的框架。通过 GRPO/PPO 算法，让模型学会在推理过程中主动调用外部搜索引擎获取信息。

**核心贡献**
1. 多轮推理机制：模型可以多次搜索直到得到满意答案
2. 统一训练框架：整合 RL 和搜索引擎
3. 灵活扩展：支持多种模型、算法、检索器

**技术难点**
1. 稀疏奖励：只有最终答案有奖励，需要有效信用分配
2. 多轮交互：需要管理状态、处理搜索动作
3. 分布式训练：需要高效的多 GPU 协调

## 11.6 面试常见问题

### Q: 为什么选择 GRPO 而不是 PPO？

回答要点：
1. GRPO 更简单，不需要训练 Critic
2. GRPO 在推理任务上效果好（DeepSeek-R1 验证）
3. GRPO 内存效率高，适合资源有限的情况
4. 但 PPO 更通用，适合需要精确价值估计的任务

### Q: 如何处理稀疏奖励？

回答要点：
1. 使用 GAE 平衡偏差和方差
2. 设计更丰富的奖励结构（如格式奖励、搜索奖励）
3. 增加训练样本的组大小
4. 使用课程学习，从简单到复杂

### Q: Search-R1 的局限性和改进方向？

局限：
1. 只支持搜索工具，可扩展性有限
2. 奖励函数简单，依赖答案匹配
3. 训练成本较高

改进方向：
1. 添加更多工具（代码执行、数据库查询）
2. 使用更复杂的奖励（人类反馈、AI 反馈）
3. 结合其他 RL 算法（DPO、PPO变体）

### Q: 如何评估 Agent 的有效性？

指标：
1. 任务完成率
2. 答案准确率（EM、F1）
3. 搜索效率（平均轮次、搜索质量）
4. 效率指标（throughput、延迟）
