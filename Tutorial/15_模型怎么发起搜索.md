# 15. 模型怎么发起搜索

这一章回答的问题是：

**模型在 Search-R1 里是怎么“发起一次搜索”的？**

注意，这里说的不是“模型调用了某个 Python 函数”，而是：

1. 模型先输出特定格式的文本
2. 系统再把这段文本解释成一个搜索动作
3. 然后去调检索服务

---

## 15.1 核心文件

最核心的文件是：

- [`search_r1/llm_agent/generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:1)

这个文件的职责可以概括成一句话：

**管理一次带搜索能力的 rollout 循环。**

它负责：

- 调模型生成
- 解析模型输出是 `search` 还是 `answer`
- 如果是 `search`，就调检索服务
- 把检索结果包成 `<information>...</information>`
- 再送回模型继续生成

## 15.3 真正的主循环在哪里

主流程在 [`run_llm_loop()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:220)：

```python
def run_llm_loop(self, gen_batch, initial_input_ids: torch.Tensor) -> Tuple[Dict, Dict]:
```

这个函数控制的是：

```text
一批样本如何多轮生成
```

你可以把它理解成下面这个循环：

```text
当前 prompt
-> 模型生成一段文本
-> 系统检查是不是 search
-> 如果是 search 就去查资料
-> 把资料拼回 prompt
-> 再生成
-> 直到 answer 或达到最大轮数
```

## 15.4 模型不是“调用函数”，而是“输出特定标签”

这点特别重要。

模型发起搜索，不是像程序员写代码那样：

```python
search("query")
```

而是输出一段文本，比如：

```text
<search>who is mike barnett</search>
```

系统再把这段文本识别成搜索动作。

训练数据里已经把这个协议教给模型了，见上一章：

- [`Tutorial/14_训练数据长什么样.md`](/Users/icarus/Documents/Search-R1-main/Tutorial/14_训练数据长什么样.md:1)

## 15.5 模型生成后先做什么

在主循环里，先调用模型生成：

- [`generation.py`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:243)

```python
rollings_active = DataProto.from_dict({
    k: v[active_mask] for k, v in rollings.batch.items()
})
gen_output = self._generate_with_gpu_padding(rollings_active)
```

这里的 `gen_output` 就是模型当前这一步生成的结果。

然后会进入：

- [`_postprocess_responses()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:54)

```python
responses_ids, responses_str = self._postprocess_responses(gen_output.batch['responses'])
```

这个函数做的事是：

```text
如果模型生成到了 </search>，就截断到 </search>
如果模型生成到了 </answer>，就截断到 </answer>
```

对应代码：

```python
responses_str = [resp.split('</search>')[0] + '</search>'
         if '</search>' in resp 
         else resp.split('</answer>')[0] + '</answer>'
         if '</answer>' in resp 
         else resp
         for resp in responses_str]
```

也就是说，系统只保留“这一步动作”的有效部分。

## 15.6 系统怎么判断这是 search 还是 answer

核心在 [`postprocess_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:407)：

```python
pattern = r'<(search|answer)>(.*?)</\1>'
match = re.search(pattern, prediction, re.DOTALL)
```

这句正则表达式会匹配两种格式：

```text
<search>...</search>
<answer>...</answer>
```

如果匹配成功：

```python
content = match.group(2).strip()
action = match.group(1)
```

例如：

```text
<search>Who is Mike Barnett?</search>
```

会被解析成：

```text
action = "search"
content = "Who is Mike Barnett?"
```

如果匹配不到：

```python
action = None
content = ''
```

这说明模型这一步输出格式无效。

## 15.7 真正“执行搜索动作”的地方

接下来进入 [`execute_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:353)：

```python
cur_actions, contents = self.postprocess_predictions(predictions)
```

先把所有动作解析出来，再收集所有 `search` 查询：

```python
search_queries = [content for action, content in zip(cur_actions, contents) if action == 'search']
```

如果当前允许搜索：

```python
search_results = self.batch_search(search_queries)
```

也就是说，**模型发起搜索的本质就是：**

```text
模型生成 <search>query</search>
-> 系统正则解析出 query
-> 系统把 query 发给检索服务
```

## 15.8 搜索之后系统返回给模型什么

在 [`execute_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:390)：

```python
elif action == 'search':
    next_obs.append(f'\n\n<information>{search_results.pop(0).strip()}</information>\n\n')
    dones.append(0)
```

这里说明：

- 如果模型这一步选择 `search`
- 系统不会立即结束
- 而是把检索结果包装成：

```text
<information>检索结果文本</information>
```

然后放进下一轮 observation，让模型继续思考和生成。

所以一个真实的多轮过程可能是：

```text
问题 prompt
-> 模型输出 <search>Mike Barnett CSKA Moscow general manager</search>
-> 系统返回 <information>Doc 1... Doc 2...</information>
-> 模型继续生成
-> 最终输出 <answer>Sergei Fedorov</answer>
```

## 15.9 如果模型格式写错了怎么办

还是在 [`execute_predictions()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:395)：

```python
else:
    next_obs.append(f'\nMy previous action is invalid. \
If I want to search, I should put the query between <search> and </search>. \
If I want to give the final answer, I should put the answer between <answer> and </answer>. Let me try again.\n')
```

也就是说，格式错了不会立刻报错退出，而是：

- 给模型一个错误提示
- 告诉它应该用哪种标签格式
- 再给它一次机会

这是一个典型的 agent-style 交互设计。

---

## 15.10 下一轮是怎么继续的

如果这一步是 `search`，那系统拿到 `<information>...</information>` 后，要把它重新拼回上下文。

关键位置是：

- [`_process_next_obs()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:77)
- [`_update_rolling_state()`](/Users/icarus/Documents/Search-R1-main/search_r1/llm_agent/generation.py:93)

这两个函数做的事情是：

```text
把本轮 response
+ 本轮 observation（也就是 information）
重新拼成下一轮模型输入
```

所以 `run_llm_loop()` 的循环才成立。

---

## 15.11 一句话看完整调用链

```text
run_llm_loop()
-> 模型生成 response
-> _postprocess_responses()
-> postprocess_predictions()
-> 如果 action == search
   -> batch_search()
   -> 返回检索结果
   -> 包成 <information>...</information>
   -> _update_rolling_state()
   -> 下一轮继续生成
-> 如果 action == answer
   -> 结束该样本
```

**Search-R1 里模型“发起搜索”并不是直接调用 Python 函数，而是输出 `<search>query</search>` 这种动作文本；系统再把它解析成真实检索请求，并把返回结果包装成 `<information>...</information>` 送回下一轮上下文。**
